# 交互层设计 · 你指挥它（v1）

> 日期：2026-11-17 · 状态：待批准 · 类型：一个子系统（输入 → 意图 → 执行）
> 前提：不改硬件、不花钱、全部软件。

---

## 1. 一句话

**你说一句、比一个手势，它就在三维空间里做出一个动作**；动作表和节奏都放在一个用户能改的文件里，人格体现在「怎么动」，不体现在「要不要动」。

---

## 2. 为什么这样切

原设计是「它自己决定什么时候动」。现在的决定是：**你来决定**。

这不是把人格删掉，是把它挪了位置：

| | 原来 | 现在 |
|---|---|---|
| 谁决定动 | 行为层 | 你（语音/手势/键盘） |
| 人格在哪 | 何时动、动几次 | 怎么动：起步犹豫、路线绕远、落定回弹、快慢 |
| 开放给谁 | — | 动作表 + 节奏参数，用户直接改 |

所以这一层的边界很清楚：**它不做决定，它只执行得很好看。**

---

## 3. 三层结构

```
┌──────────────┐   意图 JSON     ┌──────────────┐   动作      ┌──────────────┐
│ 输入          │ ─────────────→ │ 动作表        │ ─────────→ │ Blender 执行  │
│ 键盘/手势/语音 │   UDP :4590    │ actions.json │            │ 运动/表情/朝向 │
└──────────────┘                └──────────────┘            └──────────────┘
                                      ↑
                                  用户改这里
```

### 3.1 意图协议

一行一个 JSON，UDP 发到 `127.0.0.1:4590`：

```json
{"intent":"come","src":"voice","conf":0.91}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `intent` | 是 | 动作名，必须在动作表里存在 |
| `src` | 否 | `key` / `gesture` / `voice` / `api`，只用于显示 |
| `conf` | 否 | 0–1；低于动作表里的阈值就忽略 |
| `args` | 否 | 动作参数，例如 `{"dz":120}` |

- 为什么用 UDP：不阻塞、不需要握手、`echo` 一条就能测；识别进程崩了不会拖死 Blender。
- Blender 侧用后台线程收，主线程每 50 ms 取一次队列——**绝不在后台线程碰 bpy**。

### 3.2 动作表 `blender/actions.json`

```json
{
  "version": 1,
  "min_conf": 0.5,
  "styles": {
    "soft":   {"vmax": 260, "hesitate": 0.35, "detour": 1.0, "rebound": 4},
    "normal": {"vmax": 356, "hesitate": 0.0,  "detour": 1.0, "rebound": 4},
    "quick":  {"vmax": 500, "hesitate": 0.0,  "detour": 0.8, "rebound": 2}
  },
  "actions": {
    "come":  {"target": "near_person", "style": "soft"},
    "back":  {"target": "home",        "style": "soft"},
    "up":    {"delta": [0, 0, 120],    "style": "normal"},
    "down":  {"delta": [0, 0, -120],   "style": "normal"},
    "left":  {"delta": [120, 0, 0],    "style": "normal"},
    "right": {"delta": [-120, 0, 0],   "style": "normal"},
    "look":  {"face": "person",        "style": "normal"},
    "stop":  {"hold": true}
  },
  "bindings": {
    "key":     {"1": "come", "2": "back", "3": "up", "4": "down", "5": "look", "0": "stop"},
    "gesture": {"wave": "come", "palm": "stop", "point_up": "up", "point_down": "down"},
    "voice":   {"过来": "come", "退后": "back", "上来": "up", "下来": "down", "看我": "look", "停": "stop"}
  }
}
```

- 用户加动作 = 加一行；改节奏 = 改 `styles`；换口令 = 改 `bindings`。**不需要碰代码。**
- `target` 是命名点（`home` / `near_person` / `far_corner`），在场景里用空物体标出来，用户可以在 Blender 里拖。
- 未知意图 → 面板写「不认识的指令」，不崩。

### 3.3 执行层

- **移动**：复用现有 S 曲线（五次多项式）+ 落定回弹；`hesitate` = 起步前静置的秒数（0.35 s 就是「犹豫」）。
- **绕路**：`detour` 是路径绕开禁区的权重，直接沿用 `tools/plan.py` 的 A*。
- **朝向**：转 `ball_root` 的 Z 轴对着人（球是球体，转脸即可；四根线挂在吊点上，不受影响）。
- **表情**：v1 只做三档——待命（灯带暗）、在听（暖色慢呼吸）、执行（亮一下再落回）；用现有灯带和窗口材质改发光颜色与强度。
- **失败**：目标在禁区里 → 停在边界 + 面板写「安全层否决」；目标绷不住 → 停在最后一个力封闭点 + 面板变红。

## 4. 场景里的人

- 一个坐在桌前的简化人形：躯干胶囊 + 头 + 一条朝向线（眼睛方向）。不做五官，不做骨骼动画。
- 人的位置固定在桌前。`near_person` 不是「正前方」——正前方是显示器和视野中心，文档早就避开了——而是**默认侧位 `(-380, 520, 1300)`**：距眼约 640 mm、偏正前约 30°、在可飞区内。
- 手势/语音识别接进来之前，人的朝向可以直接用 Blender 里拖的箭头改，方便演示「它看你」。

---

## 5. 输入进程（识别跑在哪）

**结论：识别不放进 Blender。**

```
recognizer.py（独立进程，可关可换）
  摄像头 → MediaPipe Hands → 离散手势
  麦克风 → 唤醒词 → 命令词
              ↓  UDP
        Blender 里的 cmd_runtime.py
```

| 方案 | 取舍 | 结论 |
|---|---|---|
| 独立进程 + UDP（选定） | 崩了不影响 Blender；可单独测；以后能换手机/网页/树莓派 | ✅ |
| 全塞进 Blender 的 Python | 一个 .bat 启动 | ❌ 装库会污染 Blender、GIL 卡视图、崩了整个场景没了 |
| 先只做键盘，识别以后接 | 最省，但少了两个输入通道 | 作为第一步的脚手架，不是最终形态 |

### 已知环境风险（必须先实验）

这台机器的系统 Python 是 **3.14**，而 MediaPipe 目前只到 3.12；OpenCV、numpy 也都没装。

三条路，按推荐顺序：

1. **单独装 Python 3.12**（免费），识别进程用它；Blender 不受影响。
2. 用 **Blender 自带的 Python 3.11** 装这些库，另起一个 Blender 进程专跑识别（丑，但不用装 Python）。
3. 先只做键盘 + 动作表，识别等实验通过再接。

这条实验要花 20 分钟，做完才知道 1 还是 2。**设计不依赖它，协议不变，输入随时能换。**

## 6. 非目标

- 不做连续手势跟随（手往哪移、球往哪移）。
- 不做「指着任意一个三维点」——那要标定摄像头和工位，留到有桌面摄像头之后。
- 不做自动行为/主动靠近。
- 不做语音合成（TTS）和对话；这一步只做「听指令」。
- 不做记忆和性格（下一步，B4）。

## 7. 反目标

- ❌ 不把动作写死在代码里——进 `actions.json`。
- ❌ 不让输入进程直接改 Blender 场景——只发意图。
- ❌ 不为演示造假：球走的每一步都要过张力与禁区检查。

---

## 8. 完成标准

1. 键盘按 `1`，球从待命位走到默认侧位 `(-380,520,1300)`（不是显示器正前方），起步前停 0.35 s，停下回弹 4 mm；面板实时显示。
2. 按 `3`/`4`，球升高/降低 120 mm；按 `5`，球转向人。
3. 把 `actions.json` 里的 `come` 目标改到另一个命名点，重开就生效，不改代码。
4. `echo '{"intent":"come"}' | nc -u 127.0.0.1 4590` 能让球动（证明协议成立）。
5. 发一条不存在的意图，面板写「不认识的指令」，不崩。
6. 目标在禁区里，球停在边界并写「安全层否决」。
7. 表情：待命暗、在听暖色呼吸、执行时亮一下。
