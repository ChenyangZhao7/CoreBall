# 三维指挥 · 数字孪生网页 · 设计（短）

> **已废弃**：改用 Blender 方案，见 `2026-11-17-blender-command-design.md`。
> 日期：2026-11-17 · 状态：废弃 · 类型：小改动（单文件，无依赖）

## 要做什么

一张可以直接打开的 HTML：**在浏览器里自由地指挥这颗球在三维空间里移动**，四根线实时重算线长与张力，禁区实时挡住它。不碰硬件，不依赖任何外部库，断网也能开。

## 为什么

version 1 是「它在那儿」。实物之前，先用最低成本让人**亲手拖一下**就知道：它在三维里怎么动、四根线怎么跟着绷、为什么有些地方去不了。这比渲染图更能说服人，也比视频更能说明"可指挥"。

## 目标

- 拖一个目标点，球按 S 曲线过去（356 mm/s、1 m/s²、落定回弹 4 mm）。
- 四根线实时更新线长（mm）与张力（N），最松那根上色：绿 / 黄 / 红。
- 拖进脖子禁区（r210 圆柱）→ 球停在边界，HUD 说明"安全层否决"。
- 转到球背后看、拉近看，线不会穿帮。
- 单文件 `web/command.html`，双击即开。

## 非目标

- 不做后端、不做账号、不做手机适配。
- 不引入 Three.js 或任何 CDN 依赖。
- 不模拟球的自转/表情/灯带（下一步再说）。
- 不做真实物理（无摆动、无风）；只做运动学 + 张力静力学。

## 反目标

- ❌ 不做成"一段动画"——必须能实时改目标。
- ❌ 不做成只能走预设点——任意点都能给。
- ❌ 不为了好看牺牲数字：线长和张力必须和 `tools/tension.py` 算出来的一致。

## 场景（用真实数字，不另造）

| 元素 | 值 | 出处 |
|---|---|---|
| 四个锚点 | (±760, 217, 1729) / (±603, 850, 1729) | 参数表 |
| 球 | φ80，默认位 (−380, 520, 1300) | 参数表 |
| 禁区 | 脖子 (0, 890, 1180)，r210 圆柱 | 设计决定 18 |
| 桌子 | 1560 × 700 × 740 | 参数表 |
| 显示器 | 620 × 360 | 参数表 |

场景里只放：地面网格、桌子、显示器、红色半透明禁区圆柱、四个锚点、四根线、球、一个幽灵目标点。人只用一个立在地上的细柱示意，不建模五官。

## 交互

| 操作 | 行为 |
|---|---|
| 左键拖空白 | 转视角（环绕） |
| 滚轮 | 拉近 / 拉远 |
| 拖幽灵目标点 | 在水平面上移动目标（X/Y） |
| 高度滑杆 / PageUp·PageDown | 改目标高度（Z） |
| 方向键 | 微调目标 |
| 空格 | 回待命位 |
| 右键拖 | 平移视角 |

目标点被拖到禁区里时，目标点变红，球停在 r210 边界上——这是"安全层只许否决"的可视化。

## 画面规则

- 线色 = 最松张力：≥1.0 N 绿，0.3–1.0 N 黄，<0.3 N 红并显示"力封闭失效"。
- 球用径向渐变画成有体积的圆；线按深度排序，该在球后面的就画在后面。
- HUD 常驻：球坐标、四根线长、四根张力、最松余量、是否力封闭。

## 完成的标准

1. 打开就能转、能拉近、能拖目标；球在 356 mm/s、1 m/s² 的限制下平滑过去，停下有 4 mm 回弹。
2. 把目标拖到默认位附近，四根线长与 `python tools/tension.py -380 520 1300` 的差 < 2 mm，张力差 < 0.05 N。
3. 把目标拖进脖子禁区，球停在 r210 上，不进圆柱。
4. 把目标拖到贴墙/低处，线变红，HUD 写明"最松张力不足，物理上绷不住"。
5. 断网打开，功能不变。
